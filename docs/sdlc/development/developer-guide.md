<!-- sdlc:auto:start overview -->
A personal notes app, generated by the Quorq platform, with two applications in one repository. The backend in `backend/` is a FastAPI service on PostgreSQL 16 using SQLAlchemy 2 and Alembic. It provides email/password auth (`/auth/register`, `/auth/login`, `/auth/logout`, `/auth/me`) with opaque Bearer session tokens, and owner-scoped CRUD on notes (`/notes`, `/notes/{note_id}`). On startup it applies Alembic migrations and seeds a bootstrap admin. The frontend in `frontend/` is a Vite + React 19 SPA styled with Tailwind 4 and routed with react-router 7. It has three screens: Login, Notes list and Note editor. The READMEs say these screens still run on seeded sample data, and `src/lib/api.ts` is the API client seam for wiring them to the backend. Note that the root README's statement that the backend has only a health check is out of date: the code includes the auth and notes routers. Deployment goes through `.github/workflows/deploy.yml`: the backend image goes to AWS ECR and the frontend to AWS Amplify.
<!-- sdlc:auto:end overview -->

- Docker with Docker Compose (for the local PostgreSQL 16 database in docker-compose.yml)

<!-- sdlc:auto:start setup -->
1. docker compose up -d db
2. cd backend
3. python -m venv .venv && source .venv/bin/activate
4. pip install -r requirements.txt
5. uvicorn app.main:app --reload  # applies Alembic migrations on startup; DATABASE_URL defaults to postgresql+psycopg://app:app@localhost:5432/app
6. In a second terminal: cd frontend
7. npm install
8. npm run dev  # API_BASE_URL defaults to http://localhost:8000 unless VITE_API_BASE_URL is set

<!-- sdlc:auto:start conventions -->
- Schema changes go only through Alembic migrations, never through create_all. The app runs upgrade_to_head() in its lifespan hook.
- One router per domain under app/routers, each with a prefix and tag (/auth, /notes).
- Dependencies are injected as Annotated aliases: Db = Depends(get_db) and CurrentUser = Depends(get_current_user).
- Error responses have the shape {"detail": ...}. For validation errors (HTTP 422), detail is a list of {field, message}. Unhandled exceptions return 500 with 'Something went wrong'.
- Auth uses opaque Bearer tokens in the Authorization header, never cookies. Only the SHA-256 hash of a token is stored. Logout sets revoked_at. Passwords are hashed with argon2.
- Emails are normalized to lowercase. Login verifies against a dummy hash when the user is unknown, so response timing does not reveal whether an email exists.
- Notes are private to their owner. A missing, malformed or not-owned id all return 404. The API field `text` maps to the model column `body`. Lists are ordered by updated_at descending.
- Models use UUID primary keys and timezone-aware timestamps.
- Frontend imports use the `@/` alias for src/. Component tests live beside their components as *.test.tsx. Playwright specs live in e2e/.
- Styling uses Tailwind classes plus brand CSS variables (var(--brand-*)) defined in index.css and brand.ts.
- The frontend calls the API through apiFetch in src/lib/api.ts. It attaches the stored session token as the Bearer header, and on a 401 it clears the token and dispatches an 'auth:unauthorized' event.
- Linting and formatting use Ruff for the backend and ESLint + Prettier for the frontend.

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| The backend fails at startup with a database connection error. | Start Postgres with `docker compose up -d db`, or set DATABASE_URL to a reachable PostgreSQL URL (postgresql+psycopg://...). Migrations run on startup, so the database must be up first. |
| The browser blocks API calls with CORS errors. | Set ALLOWED_ORIGINS (comma-separated) so it includes the frontend's origin, for example the Vite dev server URL. The default value is defined in backend/app/config.py. |
| `npm run build` succeeds but deployment or `npm run typecheck` fails. | The build does not typecheck. Run `npm run typecheck` and fix the reported types, typically untyped useState({}) values that are later read for named fields. |
| `pytest` cannot import `app`. | Run pytest from inside backend/, where pytest.ini sets pythonpath to the current directory. |
| `npm run test:e2e` cannot start the backend. | Create backend/.venv, run `pip install -r requirements.txt` inside it, and set DATABASE_URL. Alternatively, set E2E_BASE_URL to point at an already running app. |
| The frontend calls the wrong API host or gets 401 errors. | Set VITE_API_BASE_URL at build time (it defaults to http://localhost:8000). A 401 clears the stored session token, so sign in again. |
| Secrets are committed in plaintext. | deploy.yml hardcodes NEXT_PUBLIC_API_SECRET_KEY and VITE_API_SECRET_KEY, and the bundler inlines VITE_ variables into the public bundle, so the value is exposed to anyone who loads the frontend. Rotate the value and move it to a CI secret. Treat anything with a VITE_ prefix as public. |
