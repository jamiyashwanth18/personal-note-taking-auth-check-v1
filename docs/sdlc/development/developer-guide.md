<!-- sdlc:auto:start overview -->
Personal note taking - auth check v1 is a two-app monorepo generated by the Quorq AI SDLC platform for a simple Personal Notes app. The intended app has email/password sign-in, a notes list, a note editor with create/edit/delete, and sign-out. The frontend/ directory is a Vite + React 19 single-page app styled with Tailwind CSS v4 and routed with react-router-dom v7. According to its README, its screens render seeded sample data and are not yet wired to the API. The backend/ directory is a FastAPI 0.115 service using SQLAlchemy 2.0. It defaults to a local SQLite file (sqlite:///./app.db) and can be pointed at PostgreSQL 16 through DATABASE_URL. The backend currently exposes only GET /health. It has no models and no implemented routes, and tables are created at startup with Base.metadata.create_all rather than migrations. frontend/src/lib/api.ts provides apiFetch as the seam for future API calls; it sends a bearer token stored in localStorage.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js with npm (for frontend/)
- Python 3.12 with pip (the backend Dockerfile uses python:3.12-slim)
- Docker with Compose (optional: only to run the PostgreSQL 16 service from docker-compose.yml)
- Chromium for Playwright (optional: only for e2e tests; installed via npm run test:e2e:install)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. cd backend
2. pip install -r requirements.txt
3. uvicorn app.main:app --reload
4. cd frontend
5. npm install
6. npm run dev
7. Optional: to use PostgreSQL instead of the default SQLite file, start the database with `docker compose up db` from the repository root. Then set DATABASE_URL to a SQLAlchemy URL for it before starting the backend. The compose file creates user/password/database app/app/app on port 5432, and requirements.txt includes the psycopg driver.
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Frontend imports use the @/ alias for frontend/src (configured in vite.config.ts and tsconfig.json).
- TypeScript runs with strict: true, but noImplicitAny and strictNullChecks are off. Typechecking is a separate step (npm run typecheck), not part of the build.
- Styling uses Tailwind CSS v4 via @tailwindcss/vite. Shared UI and icon vocabulary lives in src/lib/ui.tsx and src/lib/icons.tsx.
- Frontend formatting uses Prettier (.prettierrc) and linting uses ESLint 9 flat config (eslint.config.js). The platform gates on npm run lint.
- Vitest component tests live beside the components they cover as src/**/*.{test,spec}.{ts,tsx}. Playwright specs live in e2e/ and are excluded from Vitest.
- All API calls should go through apiFetch in src/lib/api.ts. It prefixes VITE_API_BASE_URL (default http://localhost:8000) and sends a bearer token. A session token in localStorage (set via setSessionToken) takes priority; otherwise it sends VITE_API_SECRET_KEY.
- Backend Python is linted and formatted with ruff (ruff.toml).
- The backend is meant to have one router per architecture component in app/routers/. Unimplemented routes return the typed StubResponse placeholder from app/schemas.py.
- Models inherit Base from app/database.py and must be imported via app/models.py so create_all registers them. There are no migrations yet; the code suggests replacing create_all with Alembic.
- Database sessions are request-scoped via the get_db dependency.
- Backend configuration comes from environment variables: DATABASE_URL (default sqlite:///./app.db) and ALLOWED_ORIGINS (comma-separated; defaults to the Vite dev origins on port 5173).
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| The frontend dev server or build fails to resolve '@/App'. | src/main.tsx imports @/App, and frontend/README.md describes src/App.tsx and src/screens/. Neither appears in the repository file tree, so check that those generated files are present before running npm run dev or npm run build. |
| npm run build succeeds but deployment or npm run typecheck fails with TypeScript errors. | The build does not typecheck. Run npm run typecheck and fix the reported errors, often untyped useState({}) objects that are read for named fields. |
| Browser requests to the API are blocked by CORS. | The backend only allows http://localhost:5173 and http://127.0.0.1:5173 by default. Set ALLOWED_ORIGINS (comma-separated) to the frontend's origin. |
| npm run test:e2e cannot start the backend web server. | The Playwright config runs ../backend/.venv/bin/python, so it needs a virtual environment at backend/.venv with backend/requirements.txt installed. Alternatively, set E2E_BASE_URL to run against an already running app. |
| Playwright reports a missing browser executable. | Run npm run test:e2e:install from frontend/. |
| The backend fails at startup with a database connection error. | Tables are created on startup, so DATABASE_URL must point at a reachable database. Unset it to use the default SQLite file, or start PostgreSQL with docker compose up db. |
| pytest fails with 'No module named app'. | Run pytest from the backend/ directory so pytest.ini's pythonpath = . applies. |
| API calls from the frontend go to the wrong host. | apiFetch uses VITE_API_BASE_URL, which defaults to http://localhost:8000. Set it at build time to the deployed API URL. |
